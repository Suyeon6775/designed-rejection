# 설계된 거절 : 보이지 않는 가이드라인

빌드나 외부 라이브러리가 필요 없는 모바일 도슨트입니다. 홈 + 5개 메뉴 + 10개 밈 상세, 총 16개 화면을 제공합니다. 모든 경로는 상대경로이며 `#/meme/01` 형식으로 직접 접속·새로고침·브라우저 뒤로가기를 지원합니다.

## 바로 열기

index.html을 브라우저에서 열면 됩니다. 권장 로컬 실행 방법은 이 폴더에서 터미널을 열고 다음 명령을 실행하는 것입니다. Python 3가 설치되어 있어야 합니다.

```sh
python3 -m http.server 8000
```

브라우저에서 http://localhost:8000 을 여세요. 종료는 터미널에서 Ctrl+C입니다.

## 내용 수정

- `content.js`: 프로젝트 소개, 세 다이 설명, 10개 밈 제목·질문·해설·사진·영상 경로
- `styles.css`: 여백, 글자 크기, 검은 그래픽 배치
- `app.js`: 화면 템플릿과 메뉴·경로 처리
- `assets/`: 실물 사진·영상 파일

예를 들어 assets 폴더에 newspaper.jpg를 넣은 다음, content.js의 newspaper 항목 안 media를 아래처럼 수정합니다.

```js
"media": {
  "src": "assets/newspaper.jpg",
  "type": "image",
  "alt": "신문 다이의 전체 전경",
  "caption": "신문 다이, 전시 전경"
}
```

영상은 `type`을 `video`로, `src`를 `assets/tv.mp4`처럼 지정합니다. 이미지와 영상은 로컬 assets 폴더의 상대경로를 사용하세요. 파일명은 영문 소문자와 하이픈을 권장합니다. 빈 src는 교체 예정 플레이스홀더로 표시합니다. 음성이 있는 영상은 자막과 대본도 추가해 주세요.

## 콘텐츠 기준

기존 대화에서 확인된 신문·버디버디 메신저·브라운관 TV와 10개 사례를 바탕으로 웹 해설을 새로 편집했습니다. 실물 사진·영상, 최종 밈 제목·번호의 확정 자료는 제공되지 않았으므로 해설은 초안이며 작품과 대조해 수정해야 합니다. 작가명·전시장·일정 등 미확인 정보는 임의로 넣지 않았습니다. 고주파 소리는 재생하지 않습니다.

## GitHub Pages 배포

1. GitHub에서 새 공개 저장소를 만듭니다. 예: `designed-rejection`.
2. 이 폴더 **안의 파일들**을 저장소 최상위에 올립니다. index.html이 최상위에 있어야 합니다. assets 폴더도 포함하고 `.nojekyll`도 유지하세요.
3. 저장소 Settings → Pages → Build and deployment에서 Source를 **Deploy from a branch**, Branch를 **main**, 폴더를 **/(root)**로 선택하고 Save합니다.
4. 배포가 완료되면 Pages 설정에 표시된 실제 주소로 접속합니다. 보통 `https://계정명.github.io/designed-rejection/` 형식입니다.
5. 휴대폰에서 메뉴, 10개 상세 화면, 브라우저 뒤로가기와 이미지·영상을 확인합니다.
6. 이후 같은 저장소에서 파일을 수정하고 커밋하면 같은 주소로 업데이트됩니다. 반영에 시간이 걸릴 수 있습니다.

공식 안내: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## QR 만들기

배포 후 실제 작동하는 **홈 주소**를 복사하고, QR 생성 도구의 URL 항목에 붙여 넣어 정적 QR을 만드세요. PNG 또는 SVG로 저장한 뒤 인쇄합니다. 유료 리디렉션 서비스에 의존하지 않고 배포 주소 자체를 담는 방식을 권장합니다.

파일로 생성하려면 Python 환경에서 다음을 실행할 수도 있습니다.

```sh
python3 -m pip install 'qrcode[pil]'
python3 -m qrcode 'https://YOUR-ID.github.io/designed-rejection/' > exhibition-qr.png
```

반드시 YOUR-ID와 저장소 이름을 실제 배포 주소로 바꾸세요. 배포 전 임시 주소로 인쇄하지 마세요. 휴대폰 카메라로 저장한 QR과 실제 크기의 인쇄물을 각각 스캔해 확인하세요. 흰 여백을 잘라내거나 검은 그래픽을 겹치지 마세요.

동일한 배포 주소를 유지하면 내용·사진·영상을 바꿔도 QR을 다시 인쇄할 필요가 없습니다. 계정·저장소 이름·도메인·배포 위치가 바뀌면 주소가 달라질 수 있습니다. 밈 개별 QR이 필요하면 `#/meme/01`처럼 상세 주소를 사용하고 해당 번호 경로를 유지하세요.

## 접근성과 검증

한국어 문서 언어, 본문 바로가기, 키보드 초점 표시, 네이티브 대화상자 메뉴(초점 제한·Esc 닫기), 메뉴 상태 안내, 화면 전환 후 본문 초점, 이미지 대체 텍스트, 동작 감소 설정을 적용했습니다. 5개 메뉴와 모든 상세 경로의 렌더링·문법 검사를 통과했습니다. 로컬 미리보기 브라우저 연결 실패로 실제 브라우저 화면 및 휴대폰 검증은 완료하지 못했습니다. 배포 전에 기기에서 최종 확인해 주세요.
